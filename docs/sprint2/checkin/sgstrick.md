## What is one thing you learned about the codebase or about software engineering practice?

One this I have learned about the code base is how it is organized. In Sprint 0, I was mainly focused on understanding the app and using Agent AI tools to help code. I didn't put very much effort into understanding the code base because the issues I worked on spanned only a few files, and only changed a few lines of code. The issues I worked on in Sprint 1 and continue to work on in Sprint 2, however, span many files and affect hundreds of lines of code. I have had to remember which files are nested in which folders and how those folders relate to one another. When searching through them to change the hard-coded icon sizes, I had to understand which parts of the UI the folders affected, and which ones were relevant to the issue at hand.

## What is one thing you would do differently?

One thing I would do differently is give myself more time to work on my issues. My team is very good at organizing the Sprint early on, but I have lagged behind on my own issues in each Sprint. I am a Computer Science and Theatre double major and I have a job on campus, so I have very little time to sit down and work on something. I need to take advantage of the time I have when I have it to work on issues bit by bit, until I have a product my team would be happy with. I also need to be better about reviewing issues, both my own and my teammates. I tend to review my issues manually rather than writing functioning tests, which has gotten me in trouble before. I also have a hard time understand others' code at a glance, so I take a lot longer to merge PRs reliably. With a better understanding of the codebase overall, I hope to be better when merging others' PRs.
